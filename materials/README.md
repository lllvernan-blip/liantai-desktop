# 材料池

出题用的材料来源。这里的每一篇是一份**事实骨架**——从公开发表的报道里逐条抽出的事实
（一条一个事实，带数字、带限定语），不是原文，也不含原文的句子。

## 为什么在这里

材料要随应用发到用户手上，所以它跟代码走同一套流程：改动看得见（审材料就是看 diff）、
有历史、能回滚、发布与审计用的是同一份。抓取与提炼用的临时件、被判不合格的淘汰件都是
过程产物，不进这个目录。

## 一篇骨架长什么样

```
# 标题
来源：<原始地址>
发布：YYYY-MM-DD
主题：<主题一>、<主题二>

## 背景
## 做法（已经发生的）
## 成效
## 争议 / 难点
## 建议 / 主张（还没发生的）
```

五栏是按**这件事发生了没有**切的：`做法` 只装某个主体为了解决问题已经采取的措施，
`建议 / 主张` 装谁提了但还没做的。分不清就会被出题反过来利用——题干问「提出改进建议」时，
材料里躺着整段现成建议，等于把答案写在题面上。

规矩全在 `docs/材料规范.md`，这里不重复。

采编已经可以外包给别的模型做，**它们交上来的东西不能直接进这个目录**：先放进
`LIANTAI_MAT_DIR/收件箱/<来源>/`，跑一次 `intake` 验收（格式、重复、回原文核、入库判断），
过了的才搬进来。给外部模型用的提示词在 `materials/抓材料提示词.md`。

## 怎么更新

```bash
npm run materials -- fetch rmw 10        # 人民网各频道，按栏目拿最新
npm run materials -- fetch rmrb 10       # 人民日报电子版
npm run materials -- fetch gov 养老服务 3  # 政策文件库，按关键词搜
```

抓下来的东西**不合格不落盘**：入库判断不过的直接丢，地址记进 `LIANTAI_MAT_DIR/淘汰.json`，
下次抓取不再重判它（同一批候选里，进池子的会被跳过、被拒的要是也不记，每重跑一遍就白花一遍调用）。
改动当前的提炼规矩之后，用 `redo` 把池子里已有的文章重提炼一遍：

```bash
npm run materials -- redo all
```

池子变大了要发出去，见 `docs/发布与更新.md` 的「材料发布」一节。

## 验收外部交来的骨架

```bash
npm run materials -- intake            # 整个收件箱
npm run materials -- intake 豆包       # 只验一个来源
```

四种去向：**收**（重排成统一格式，改名进池子）、**退**（挪进淘汰目录，网址记进拒稿名单）、
**重复**（池子里已有，或以前判过不合格）、**待补**（留在原地，补好了再跑）。
分堆是实测定的：**编造（正文里根本没这回事）一票否决；说得比正文满的允许收，但逐条列出来**。
一篇骨架二十多条，按 8% 的噪声底，要求「一条不错」等于把这条路堵死；而编造与说满的伤害不是一回事。

另有四条判据是实测定的，别改回去：

- **空栏的「（原文未提及）」是标记，不是一条事实**。交来的写法可能带全角括号、可能只写「未提及」，判据
  得都认：认不出来它就会被当成一条真事实送回原文核，核不过按「编造」整篇退掉，网址还进拒稿名单——
  带全角括号那一形就这么退掉过一整批好稿。空栏只认这几种写法，别的写法（「暂无」「无」「—」）不算，
  所以提示词里把它写成硬规矩。
- **说得比正文满的条目要留痕**：写进骨架文件头的「待修：」一行，收尾报数。只打在终端上，换个会话就没人
  知道还欠着；而**同一篇重交会判成重复、走不回来**，那行是改稿唯一的通道。
- **同一篇换个网址写法（http/https、尾斜杠、大小写）还是同一篇**：去重按归一化后的网址比。按原串比的话，
  同篇换个写法会白核一次，还在池子里躺成两篇。
- **收件箱的「已入库清单」由这一步按池子重写**，不许手写：它是交稿方防重复的唯一依据，手写必漂。

## 审什么

发布前跑一次抽检，脚本会把条目拿回原文逐条比：

```bash
npm run materials -- verify 24
```

它只报不改——判错是人的事，脚本不该悄悄擦掉。输出里 `说过头` 与 `错` 两类要逐条看：
抽样错率长期在 8% 上下，错的全是同一族——**限定语被抹掉**（主体、语气、时间、范围）。
这个噪声底是 prompt 这一层压不动的，剩下的靠发布前这一道人工看。
