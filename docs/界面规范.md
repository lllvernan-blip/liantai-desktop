# 界面规范（质感与排版细节）

`AGENTS.md` 的「界面（UI/UX）约束」节只留行为与口径；**改界面之前必须先读这一份**，它是同一条约束的细节层。两条都别推翻：一份讲「界面上该说什么、不该说什么」，一份讲「长什么样」。

**哪些判据是硬的**：有出处的写明出处（WCAG 条款 / 同行评议实验 / 平台规范），那些是必须满足的；没写出处的就是自定，改它只要说服人，不用找依据。**逐条标出处是 2026-10-14 起的，早先的条目多数还是自定**——补到哪条算哪条。

## 字号与控件

- **字号只有五档**（`--fs-*`）：`12.5` 辅助小字 / `14` UI 正文 / `16` 区块标题 / `26` 整屏标题 / `30` 分数这类大数。**相邻至少差 1.5px**——差半像素等于没分级。字面值只留红头机关名（30）与纸上的字（16 × 5：材料、作答、范文与两处说明），其余一律走 token。**下界有依据**：Microsoft 的 Windows 设计规范给正文 14px、最小 12px（更小在部分语言不可读），我们最小档 12.5px 在其上、正文 14px 正对齐；**「相邻差 1.5px」是自定**，没有出处。
- **`<small>` 是陷阱**：不写 `font-size` 它就按浏览器的 `smaller` 算——父级 12.5px 时算出 10.4px，悄没声地掉到五档之外（修在 `.chip small` / `.typestat .t small`）。
- **控件只有两档高度**：`--h-ctl:36px`（按钮 / 输入框 / 下拉）、`--h-ctl-sm:30px`（胶囊 chip / 科目按钮 / 工具栏文字键）。
- 另有起始区主行动一档：`.startbox .primary.big` 是 `16px` 字 + `padding:16px 58px`（≈54px 高、`min-width:320px`）——纸面上只有它一件事，得占得住地方。空出来的地方不加东西（见 `AGENTS.md`「纸就是纸」）。
- 控件 `line-height` 定死 1.35，不许再继承 body 的 1.7（否则一个按钮就 40px）。

## 颜色与表面

- **设计色只走 token**：`:root` 外不写 hex（唯一例外是用户可选的划线色 `MARK_COLORS` 与 `var(--mark, …)`，那是运行时数据）。断言盯着这条。
- 淡底只有 `--wash / --wash-2 / --wash-3 / --line-soft`；语义色用 `--danger / --success / --warn`。`--warn(#b45309)` 是焦橙不是黄（「半对」与提醒句用），别再另开暗金 `#b8860b` 那种黄。
- **灰只有三档，而且下限是算出来的**：`--ink #2C2925`（结论 / 正文，14.24:1）/ `--muted #5e5e57`（元信息，6.43:1）/ `--muted-2 #76746f`（证据 / 计数 / 口径说明 / 脚注，4.59:1），三个比值都是对纸面 `--paper` 算的。**【标准】下限来自 WCAG 2.2 的 1.4.3（AA）：正文文字对比度 ≥ 4.5:1。**这条线一画，灰的可用区间只剩 4.5–6.5，**装不下第四档**——原来的 `--ink-faint: #A29C8F` 只有 2.69:1，而它用在脚注、设置弹层的分组小标题、输入框下的说明字上，全是必须看清的正文，2026-10-14 已并入 `--muted-2`。**低于 4.5:1 的灰不许用来写正文**，层次改靠字号、字重、位置分。新加文字前先问它属于哪一档。
- **表面色只三档**：`--paper`（纸）/ `--ctl #fffefb`（控件外表，**不要用裸 `#fff`**，纯白比纸面更冷更亮）/ `--mat #f6f2e7`（给定材料，比纸面明显黄一档）；`--write` 专给作答区与笔记。
- **`--head(#f2efe8)` 是暖底**：原来 `#f1f2f0` 偏冷，在暖纸面上是一块灰斑。
- **材料上的两种标记共用一套：底色 + 2px 底边线**。划线用设置里选的颜色（底边线由它加深一档），找点是暖沙（`#e9e1cc` + `inset #cdbe97`）——淡蓝 + 蓝下划线是整屏唯一的冷色，看着像超链接，不用。同一句上两种状态叠在一起时，底色归划线、底边线归找点。
- **材料区的浮标与划线小窗挂在纸面之外**（`#fabSlot` / `#popSlot`）：纸面里每个直接子元素都带入场动画，动画末帧的 `transform` 算出来是单位矩阵而不是 `none`，那个盒子因此成了 absolute 子元素的定位基准，挂在里面的浮层会被再叠一次它的偏移。
- **纸内的红要数得出来**：`.grade` 顶线已退中性（红只从 30px 分数开始）、`.ghead` 自带底线成页眉；顶栏的实心红只留主行动，科目选中是红描边胶囊。动颜色前先数一眼这屏有几处红。

## 间距与分隔

- **间距只有五档**：`4` 紧贴 / `8` 组内 / `12` 组间 / `16` 分段 / `24` 区块，直接写数值不设 token；`margin-top` 与 `gap` 不许再出现 `6/10/14/18/20/28/32` 这类中间值（中间值越多，越读不出「哪里换了一段」）。
- **容器留白不套这五档**：`.startbox`（48/36/56）与 `.doc`（40/54/56）是纸面的大留白，按纸的比例给，不参与元素间距。
- **分隔线一套**：逐条列表一律 1px 实线（`.pditem / .pickline / .barline / .mrow / .expline`），虚线只给 `.nextrow` / `.redline` 这类非实体分隔。
- **折叠三角只有一套**：12px + `var(--line-strong)`；flex 行用 `margin-left:auto`，块级 `summary` 用 `float:right`。
- 行内间距一律走上面那五档。改它要小批替换 + 全量自检全绿。

## 横向与纸面

- **横向基准只有一条**：纸面的排版基准是 760px（每行约 36 字），整张纸按窗口宽度等比放大——`--paper-scale`（1–1.5）由 `applyPaperScale()` 按窗口宽度写，**≤1050 不放大、超宽封顶 1.5**；`.toolbar` 的左右 padding 写 `max(16px,calc((100% - 760px * var(--paper-scale))/2 + 16px))`，与纸边逐像素对齐（窄窗口自动退回 16px）；任何新顶栏行都照抄。**760 不是随手定的**：减掉 `.wrap` / `.doc` / `.material` 三层左右内边距后，材料区实宽 572px，16px 汉字一行 35.75 字——落在 W3C clreq《中文排版需求》的正文 17–40 字与 WCAG 1.4.8（CJK ≤ 40 字）之内，且几乎正中 Chan 等 2014（*Human Factors*）测出的中文屏幕 36 字/行最优值。**改这个数之前先重算这三个。** 放大的是整张纸（字号、控件一起），行宽仍是 36 字；弹层 / 浮标 / 划线小窗 / 引导框在纸外，按界面尺寸与视口坐标走，**不跟着缩**。
- **纸面靠色和高度立，不靠描边投影**：`.doc` 是光板——无边框、无阴影、无圆角。纸 `--paper #fffdf8` 对底板 `--canvas #F4F1EA` 是 1.110:1，边框 `--line #d9d6cf` 对纸是 1.428:1，两个数都贴在人眼分辨的边上，**放大六倍才看得出**，正常使用距离下分辨不出（2026-10-15 实物确认）。原先那句「白纸贴在灰底上没边，看着就是个 div」是照着眼睛写的，没对着数核过。
- **细条（`.barline .bt` / `.mrow .mbar`）只能 4px + 圆头**，填充色 `--bar(#a9a49a)`。之前 6px 实心深灰是整行最重的东西、比字还重——诊断数据不该抢注意力。`--bar` 对纸面只有 2.44:1，**不过 WCAG 1.4.11 的 3:1**（那条管「理解内容所必需的图形」）——判定为**装饰**：细条旁边永远跟着数字（`均分 N` / `正确率 N%`），信息由文字承载。2026-10-14 核过，**故意不加深**（加深会让它重新变成整行最重的东西）；哪天数字挪走了，这条判定就要重来。
- **边界线的对比度按「它是不是唯一线索」分两档**：WCAG 1.4.11 只管「识别控件所必需的视觉信息」——**有文字自明的按钮不受约束**（Understanding 的 Boundaries 节、Fig 30），**空框输入框靠边指示可输入，边就必须 ≥ 3:1**（Fig 31/32/34）。所以 `--line-strong(3.34:1)` 只发给 `select / input / 作答区 / 笔记框` 这四个，`button / .chip / .pdopt` 这一批走 `--line(1.43:1)` 是**有依据的克制**，不是不一致。**别把这条读成「所有控件边都要 3:1」**——那是 2026-10-15 从注解里发现的写宽了的一句，原文的限定词是「**唯一线索**」。

## 数据列

- **数值列不抖**：分数 / 百分比 / 次数 / 字数一律 `font-variant-numeric:tabular-nums`，并给固定宽右对齐（范例：`.hist .num`、`.barline .bn/.bv`、`.mrow .mavg/.mmeta`）。**只加 CSS，不改结构或文案**——`width:NN%`、`均分 N` 这些串是断言盯着的。
- **画像的数值列是定宽右对齐，不是 min-width**：`.mavg/.mmeta` 各 `flex:0 0 84px`（「正确率 100%」宽 83px）、`.mweak` `flex:0 0 120px`。用 min-width 时宽值会把细条起点逐行往右顶（看到的就是「一列数字」实则逐行跳）；未练行也走 `.mavg`（不是 `.mmeta`），这样「未练」与「均分 N」同列、维度说明与细条同起点。

## 组件形状

- **训练链步骤条 `.flowrail` 是三枚等宽胶囊，报「进度」不是「一排按钮」，也不是题干的一部分**（申论链上只有三步：读材料 / 一稿 / 批改）：它摆在**纸面第一行**（题目之前）——它说的是「我现在在哪」，夹在作答要求与当前步面板之间会让人当它是题目的一段。三枚 `flex:1` 同宽、`--r-pill` 圆角、间距 8；`counter-reset/increment` 出序号徽标（已过 = ✓、当前 = 红底红字、未到 = 灰）。**不要改回通栏细线框**——那是表格的气质，和全站的胶囊语言打架。**它不可点（没有点击处理），所以不给 `cursor:pointer` / hover**——看着能点却点不动比没反馈更糙。
- **内容页用圆角块分组，不画通栏细线**：材料、折叠区（`.notebox`）、批改页的分数与答卷、设置的每个分组，都落在 `--wash` / `--mat` 的 `--r-card` 块里，分隔靠 24px 间距；卡片内部的清单也不画行线（`.notebox .pickline` / `.ognpts .pickline` 无底边）。**红头、红线、纸面本身不动**。新增一类分组时先问：它该是一个圆角块，还是真需要一条线——默认前者。
- **抬头下最后一行是「左边在哪、中段当前状态、右边文号」**（`.docmeta`，space-between）：左边 `.modlabel` 只报「模块 · 子类型」（科目名不进这行——科目按钮亮着、文号也带着科目名，写第三遍是凑数），右边 `.docno` 报文号。原先各自占一行、中间空出一大截（2026-10-09 合并）。**中段 `#pdState` 只在快判进行中填「主题 · 第几题 · 已对几题」**——这行原本单占纸面最前面一行，左边还挂个「快判」标题，跟红头里的文号与形式名说同一件事（2026-10-14 收进红头，`.secrow` 那行拆掉）。别把这三样拆回两行，也别再让纸面另起一行报同样的东西。
- **题头右侧的行内动作走 `.secrow`**（`justify-content:space-between`）：`换一题` 以前单占一行、孤悬在题头之上，批改页的「我的答案」也走这一套（右侧带标注图例）。注意断言盯着 `class="sec-title">题目` 这个串，包一层 `.secrow` 安全，别给 `.sec-title` 自身再加类。
- **行右侧的格子（`.secright`）只放「这一行自己的工具」**：`题目` 行是 `换一题`，`作答区` 行是归类入口（`先归类再写` / `看我归的类（N 类）`）与限时控件。新加一个页面级入口时先问它属于哪一行；**另起一行挂在两块之间就是孤零零的元素**——2026-10-09 把归类从链上一步降级成一稿页入口时，第一版单占一行，看着像没归位。
- **归类面板是一稿的子工具，不是第四步**：步骤条当前步报「一稿 · 归类」，**纸面不再起「归类」标题**（抬头已报的东西不重写）；顶上只有一行——左边一句操作提示（归点时带「已归 n / N」），右边限时 + 回到一稿。**这一屏不摆题面与「换一题」**（归类不是作答，换题会打断归类）；限时留在这行（归类的用时算作答）。第一段：**规范词（组按钮，`--fs-note` 小一号的 `--r-pill`）排在上面，当前点在下面当证据**，`+ 新建一组` 与规范词同排，已找的点收在折叠清单里；卡里的「整句」标签用纸色（浅灰底上才看得出是标签，不然会读成句子的一部分）。第二段：每组一张 `--r-card` 卡，**组名就是这一组的标题（输入框占整行、`--fs-title` 加粗），句子在下面当证据**，不另起「第 N 组」标签。**不写「第一步 / 第二步」这类步骤说明**——按钮与入口已经把话说清。**提纲不在这一屏**：它是这一段的产物，摆在写完之后的一稿页（默认收起的 `details`）——产物不摆在产地。
- **题面字段（作答要求 / 建议结构）用悬挂缩进**：`.require{padding-left:5em;text-indent:-5em}` + `.require b{display:inline-block;min-width:5em;text-indent:0}` + `.require br{display:none}`——两个标签都是 5 字，于是值从同一条竖线开始，折行也缩进到值那一列。**`b` 上的 `text-indent:0` 不能省**：`text-indent` 是继承属性，而 `inline-block` 自成块容器、会把父级那个 `-5em` 在自己的首行上再应用一次，标签的字因此被推到纸面左边缘之外（实测标签字形起点 181、纸面左沿 201）。
- **`pill / tag` 不描边**：`.pill/.etag/.ptag/.typestat .t` 都是淡底色块，不再「1px 边框 + 淡底 + 彩字」三件套（那是 Windows 复选框的气质）。
- **悬停上浮只给 `.primary` 红按钮**；其余控件悬停只换底色或描边。焦点反馈三处一致：输入框与大文本框都带 `--focus-halo` 外圈。
- **输入框里的技术串（接口地址 / API Key / 模型名）用雅黑不用仿宋**：仿宋里 l / 1 / I 长得一样。下拉候选框用 `--sh-2`（下拉浮标那一档），否则纸色底盖纸色纸背，看不出浮在上面。

## 设计语言四句话

- **控件是产品，文档是公文**：按钮 / chips / 下拉用雅黑（仿宋笔画细，小字号像没渲染完）；红头、材料、作答、范文才是仿宋 / 宋体的地盘。新控件别再默认继承仿宋。
- **清单只有一种语言**：一条顶线 + 行间细线，不套框。`.pdreview/.hist/.mrowbox/.notebox` 全部去边框盒；新增列表别再画 `.xxx{border:1px solid var(--line)}` 的盒子。
- **框只留一个，卡里不再套盒**：`.tpl`（答题框架 / 示例 / 提纲 / 差异对照）去掉 1px 边框与近白底，只留左缘 2px `--bar` 细线——原本靠它所在的学习卡提供外框，学习卡改成「常驻浮标 + 抽屉」之后（`details.card` 已下线），`.tpl` 就靠这一道线自己站住。给文本块加框前，先看它是不是已经站在某个框里。
- **主角要敢占地方**：材料 16px / 行距 2.05（作答区、范文同步）——16px 与「精读 17px」同一档（Hou 等 2020 的中文手机阅读实验）；行高 2.05 略超 clreq 建议的 1.5–2.0 倍，WCAG 1.4.12 只管下限 ≥ 1.5 倍，**这一条目前是自定、没动**；主行动按钮 40px 高 / 14px 加粗（`.primary`）；批改页分数 30px。一个屏幕里这种重量级的东西只允许一个。
- **欢迎语不穿报错的红衣服**：`banner(html)` 默认是安静的信息条（左缘 3px 红线）；只有真失败才 `banner(html, "error")`（存储写入失败、接口失败、导入失败这批）。别再让两类消息共一种样式。

## 文案笔法

- 文案写宽泛、贴用户视角，**别写死实现**：说「本地」，不说「这台电脑 / 本机浏览器 / localStorage」这类以后实现一变就要跟着改的词。
