# 界面规范（质感与排版细节）

`AGENTS.md` 的「界面（UI/UX）约束」节只留行为与口径；**改界面之前必须先读这一份**，它是同一条约束的细节层。两条都别推翻：一份讲「界面上该说什么、不该说什么」，一份讲「长什么样」。

## 字号与控件

- **字号只有六档**：12 标签 / 13 元信息与提示 / 14 行与控件 / 15 正文与材料 / 16 小节标题 / 19 大标题（红头 26 / 30 单算）。13.5 / 14.5 / 15.5 这类半像素档已全部归位，别再引入。
- **`<small>` 是陷阱**：不写 `font-size` 它就按浏览器的 `smaller` 算——父级 13px 时算出 10.8px，悄没声地掉到六档之外（修在 `.chip small` / `.typestat .t small`）。
- **控件只有两档高度**：`--h-ctl:36px`（按钮 / 输入框 / 下拉）、`--h-ctl-sm:30px`（胶囊 chip / 科目按钮 / 工具栏文字键）。
- 另有起始区主行动一档：`.startbox .primary.big` 是 `16px` 字 + `padding:16px 54px`（≈54px 高、`min-width:320px`）——纸面上只有它一件事，得占得住地方。空出来的地方不加东西（见 `AGENTS.md`「纸就是纸」）。
- 控件 `line-height` 定死 1.35，不许再继承 body 的 1.7（否则一个按钮就 40px）。

## 颜色与表面

- **颜色只走 token**：`:root` 外不写 hex。
- 淡底只有 `--wash / --wash-2 / --wash-3 / --line-soft`；语义色用 `--danger / --success / --warn`。`--warn(#b45309)` 是焦橙不是黄（「半对」与提醒句用），别再另开暗金 `#b8860b` 那种黄。
- **灰要分三档**：`--ink`（结论 / 正文）/ `--muted #5e5e57`（元信息）/ `--muted-2 #827d72`（约 4.0:1，证据 / 计数 / 口径说明 / 摘要）。只有两档灰时正文与证据糊在同一层，「不精致」多半就是这个。新加文字前先问它属于哪一档。
- **表面色只三档**：`--paper`（纸）/ `--ctl #fffefb`（控件外表，**不要用裸 `#fff`**，纯白比纸面更冷更亮）/ `--mat #f6f2e7`（给定材料，比纸面明显黄一档）；`--write` 专给作答区与笔记。
- **`--head(#f2efe8)` 是暖底**：原来 `#f1f2f0` 偏冷，在暖纸面上是一块灰斑。
- **材料区的「已点选」是暖沙（`#e9e1cc` + `inset #cdbe97`），不是淡蓝**：淡蓝 + 蓝下划线是整屏唯一的冷色，看着像超链接。
- **纸内的红要数得出来**：`.grade` 顶线已退中性（红只从 26px 分数开始）、`.ghead` 自带底线成页眉；顶栏的实心红只留主行动，科目选中是红描边胶囊。动颜色前先数一眼这屏有几处红。

## 间距与分隔

- **段落之间要拉开（28–32），组内保持 6–12**：`.sec-title` 28 / `.grade` 32 / `.notebox` 20 / `.ognow` 14 / `.nextrow` 28 / `.field` 22。全屏都是 14–20 时，眼睛分不出「哪里换了一段」，一屏就是一长条。
- **分隔线一套**：逐条列表一律 1px 实线（`.pditem / .hitline / .pickline / .barline / .mrow / .expline`），虚线只给 `.nextrow` / `.redline` 这类非实体分隔。
- **折叠三角只有一套**：12px + `var(--line-strong)`；flex 行用 `margin-left:auto`，块级 `summary` 用 `float:right`。
- 行内 `margin-top` 有 9 档（4/6/8/10/12/14/16/18/26）**尚未收敛**：都在 JS 模板串里，逐处改带回退风险；将来动它要小批替换 + 全量自检全绿。

## 横向与纸面

- **横向基准只有一条**：纸面是 `max-width:880px` 居中的，而顶栏 / 科目栏原来两端贴窗口边——一屏里两套左右基准。`.toolbar` 与 `.modbar` 的左右 padding 统一写 `max(14px,calc((100% - 880px)/2 + 14px))`，与 `.wrap` 逐像素对齐（窄窗口自动退回 14px）；任何新顶栏行都照抄。
- **纸面要像纸**：`.doc` 带 `--sh-paper`（两级极淡投影）。白纸贴在灰底上没边，看着就是个 div。
- **细条（`.barline .bt` / `.mrow .mbar`）只能 4px + 圆头**，填充色 `--bar(#a9a49a)`。之前 6px 实心深灰是整行最重的东西、比字还重——诊断数据不该抢注意力。

## 数据列

- **数值列不抖**：分数 / 百分比 / 次数 / 字数一律 `font-variant-numeric:tabular-nums`，并给固定宽右对齐（范例：`.hist .num`、`.barline .bn/.bv`、`.mrow .mavg/.mmeta`、`.hitline .sc`）。**只加 CSS，不改结构或文案**——`width:NN%`、`均分 N` 这些串是断言盯着的。
- **画像的数值列是定宽右对齐，不是 min-width**：`.mavg/.mmeta` 各 `flex:0 0 84px`（「正确率 100%」宽 83px）、`.mweak` `flex:0 0 120px`。用 min-width 时宽值会把细条起点逐行往右顶（看到的就是「一列数字」实则逐行跳）；未练行也走 `.mavg`（不是 `.mmeta`），这样「未练」与「均分 N」同列、维度说明与细条同起点。
- **采分点行是三列（要点 | 证据 | 分值）**：`.hitline .ev{order:2;flex:0 0 32%}` + `.hitline .sc{order:3;flex:0 0 52px}`。**用 `order` 只改视觉顺序，DOM 顺序不动**——所以 `hitline miss` 那些字符串断言不受影响（真删真换就得同步改断言）。批改页已不摆全量采分点， `.hitline` 现在只出现在回改页（列上一稿不达标的子项）。

## 组件形状

- **训练链步骤条 `.flowrail` 是「进度」不是「一排按钮」，也不是题干的一部分**（链上只有三步：读材料 / 一稿 / 批改）：它摆在**纸面第一行**（题目之前）——它说的是「我现在在哪」，夹在作答要求与当前步面板之间会让人当它是题目的一段。`counter-reset/increment` 出序号徽标（已过 = ✓、当前 = 红底白字）、`width:fit-content` 自成一条、段间 1px `--line-soft` 分隔、上下 1px 实线。**它不可点（没有点击处理），所以不给 `cursor:pointer` / hover**——看着能点却点不动比没反馈更糙。
- **题头右侧的行内动作走 `.secrow`**（`justify-content:space-between`）：`换一题` 以前单占一行、孤悬在题头之上。注意断言盯着 `class="sec-title">题目` 这个串，包一层 `.secrow` 安全，别给 `.sec-title` 自身再加类。
- **行右侧的格子（`.secright`）只放「这一行自己的工具」**：`题目` 行是 `换一题`，`作答区` 行是归类入口（`先归类再写` / `看我归的类（N 类）`）与限时控件。新加一个页面级入口时先问它属于哪一行；**另起一行挂在两块之间就是孤零零的元素**——2026-10-09 把归类从链上一步降级成一稿页入口时，第一版单占一行，看着像没归位。
- **题面字段（作答要求 / 建议结构）用悬挂缩进**：`.require{padding-left:5em;text-indent:-5em}` + `.require b{display:inline-block;min-width:5em;text-indent:0}` + `.require br{display:none}`——两个标签都是 5 字，于是值从同一条竖线开始，折行也缩进到值那一列。**`b` 上的 `text-indent:0` 不能省**：`text-indent` 是继承属性，而 `inline-block` 自成块容器、会把父级那个 `-5em` 在自己的首行上再应用一次，标签的字因此被推到纸面左边缘之外（实测标签字形起点 181、纸面左沿 201）。
- **`pill / tag` 不描边**：`.pill/.etag/.ptag/.typestat .t` 都是淡底色块，不再「1px 边框 + 淡底 + 彩字」三件套（那是 Windows 复选框的气质）。
- **悬停上浮只给 `.primary` 红按钮**；其余控件悬停只换底色或描边。焦点反馈三处一致：输入框与大文本框都带 `--focus-halo` 外圈。
- **输入框里的技术串（接口地址 / API Key / 模型名）用雅黑不用仿宋**：仿宋里 l / 1 / I 长得一样。下拉候选框用 `--sh-2`（下拉浮标那一档），否则纸色底盖纸色纸背，看不出浮在上面。

## 设计语言四句话

- **控件是产品，文档是公文**：按钮 / 页签 / 下拉用雅黑（仿宋笔画细，小字号像没渲染完）；红头、材料、作答、范文才是仿宋 / 宋体的地盘。新控件别再默认继承仿宋。
- **清单只有一种语言**：一条顶线 + 行间细线，不套框。`.hits/.pdreview/.hist/.mrowbox/.notebox` 全部去边框盒；新增列表别再画 `.xxx{border:1px solid var(--line)}` 的盒子。
- **框只留一个，卡里不再套盒**：`.tpl`（答题框架 / 示例 / 提纲 / 差异对照）去掉 1px 边框与近白底，只留左缘 2px `--bar` 细线——原本靠它所在的学习卡提供外框，学习卡改成「常驻浮标 + 抽屉」之后（`details.card` 已下线），`.tpl` 就靠这一道线自己站住。给文本块加框前，先看它是不是已经站在某个框里。
- **主角要敢占地方**：材料 16px / 行距 2.05（作答区、范文同步）；主行动按钮 40px 高 / 15px 加粗（`.primary`）；批改页分数 30px。一个屏幕里这种重量级的东西只允许一个。
- **欢迎语不穿报错的红衣服**：`banner(html)` 默认是安静的信息条（左缘 3px 红线）；只有真失败才 `banner(html, "error")`（存储写入失败、接口失败、导入失败这批）。别再让两类消息共一种样式。

## 文案笔法

- 文案写宽泛、贴用户视角，**别写死实现**：说「本地」，不说「这台电脑 / 本机浏览器 / localStorage」这类以后实现一变就要跟着改的词。
