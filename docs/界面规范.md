# 界面规范

`AGENTS.md` 的「界面（UI/UX）约束」节只留行为与口径，这一份是细节层的判断。改界面之前先读。

状态：动态更新。只有这一份，原地改——不标日期、不写「原来是怎样」、不存副本。取舍过程进 `docs/adr/`。

**这一份只写判断和硬线。**具体像素、类名、CSS 写法不在这里重复第二遍：代码里有，`tests/assertions.js` 盯着，那边才是真相。判据是「把句子里的标识符去掉，还剩不剩一个可执行的判断」，不剩就说明它只在描述代码现在长什么样，删掉。

**判据分两等**：有出处的（WCAG、同行评议实验、平台规范、中文排版需求）必须满足，要改先推翻出处；没出处的是自定，改它只要说服人。

## 一 设计语言（先看这一节）

- **控件是产品，文档是公文**：按钮、chips、下拉用雅黑——仿宋笔画细，小字号像没渲染完；红头、材料、作答、范文是仿宋的地盘。
- **清单只有一种语言**：一条顶线加行间细线，不套框。
- **框只留一个，卡里不再套盒**：给文本块加框前，先看它是不是已经站在某个框里。
- **主角要敢占地方**：材料 16px、`--lh-loose`（2.05），主行动加粗、分数 32px。一屏里这种重量级的东西只允许一个。
- **一行高的信息不许各占一行**：建议结构与分值/难度/换一题并一行，动笔前与限时/学习卡并一行。每条只有半句高的东西单摆，横向空一半、纵向白吃四十像素，一屏里作答框就少了两行，而它才是这一屏的主角。
- **一栏里的每一行都落在同两条竖线上**：作答要求、折叠行、动作条一律左右贴边——字数靠左、动作靠右，不把一整套按钮缩在左边、右边空出两百多像素。左栏材料块与右栏同顶同底，材料短的时候也铺满，别让它半截就断。
- **配角收起来**：作答前的经验、建议结构这类「想起来才看」的东西默认收起，标题行报一句里面有多少，点开才摊——摊在作答框上面就是跟主角抢地方。**纸面内**的折叠块趁早折——两栏时右栏是死高，展开只是把作答框压小，整页不动；单栏时展开会往下顶，那是正常的流。
- **纸面靠色和高度立，不靠描边投影**：纸是光板，无边框、无阴影、无圆角。别照着眼睛去加边，纸和底板的对比本来就贴在人眼分辨的边上。
- **日常提示不穿报错的红衣服**：默认是安静的信息条，只有真失败才走 error。

## 二 硬线（必须满足）

- **正文对比度 ≥ 4.5:1**（WCAG 2.2 1.4.3 AA）。这条线一画，灰的可用区间只剩 4.5–6.5，装不下第四档。低于这个数的灰不许用来写正文，层次改靠字号、字重、位置分。
- **空框输入框的边 ≥ 3:1**（WCAG 1.4.11）。这条只管「识别控件所必需的视觉信息」，有文字自明的按钮不受约束。判据是「它是不是唯一线索」，不是「所有控件边都要 3:1」。
- **CJK 正文 ≤ 40 字/行**（WCAG 1.4.8 与 clreq《中文排版需求》的 17–40 字），尽量落在 36 字附近（Chan 等 2014，*Human Factors*）。纸宽与分栏都受这条约束，改之前先重算。
- **纸宽了字不许跟着宽**：放大的是整张纸，行宽不变。
- **行高只有四档 token**：`--lh-ctl:1.35`（控件）/ `--lh-body:1.7`（UI 正文）/ `--lh-doc:1.85`（纸面正文）/ `--lh-loose:2.05`（阅读材料）。下限 ≥ 1.5 倍（WCAG 1.4.12），四档全过。大字号标题（红头机关名）用 1.25 不进档——它跟控件和正文都不在一套节奏里。`line-height:1` 只给单行图标图标元素（tooltip、icon button），不算排版档。不许新造字面值。
- **字号只有五档，相邻至少差 1.5px**——差半像素等于没分级。32 / 28 / 17 / 15 / 13，正文 15、最小 13；下界参照 Microsoft Windows 设计规范（正文 14、最小 12），我们各高一档。两处例外不进五档：红头机关名 30（公文抬头的规格），纸上正文 16（材料、作答、范文跟着纸走，不跟界面档位）。例外只有这两处，再多一处就说明五档不够用。
- **动效只有三档时长、两条曲线**（数字与曲线取自 Material 3 motion tokens）：状态切换、按下、入场各一档，全部 ≤240ms；曲线一条给状态互切（去与回同一条），一条给入场（起步快、落定不弹）。**不拿浏览器默认的 `ease` 凑**——它起步慢、收尾拖，同一批控件因此各走各的节奏。加新动效先选档，不新造时长。
- **间距与圆角各只有一套档**：间距 0 / 4 / 8 / 12 / 16 / 24 / 32，圆角 0 / 6 / 8 / 12 / 16 / 999。新写一处先挑档，不新造刻度。散值不会一眼看出错，只会让全站慢慢各写各的；改的时候也说不清该改哪个。`npm run audit:layout` 会把越档的列出来。

## 三 层级与主次

- **一个屏只有一档红**，其余落在「描边」或「文字键」两档，三档不混用。主次只靠红与不红分，不靠高度差——红已经够重，再高 4px 只是把一行拉歪。
- **一屏一个主行动**。判断标准是红按钮真正推的是哪件事，不是文案换没换。
- **主行动跟状态走，不跟屏走**：有未完成的练习，红按钮就是「继续」；手上没题才是「出一道题」。科目名由顶栏与文号报过，练法由抬头「综合 · 智能出题」报过，主行动只写这一下会发生的动作，不把同一件事说第三遍；但也不许只剩「开始」这种没有对象的动词——下面那排模块胶囊还没选中态时，人点之前不知道会出哪类题（2026-11-06 改）。并进主行动之后，不再另起一行说同一件事。**主行动跟清单行同高**（48）：主次本来就只该靠红分，再高出一截只是把一颗按钮拉成横幅。
- **但走不通时不许先答应**：缺 Key、缺模型时主行动仍是「先填 API Key」，恢复退回次一档。题能写、交卷仍要回头填，不能先答应再反悔。
- **危险动作不穿主行动的衣服**：确认态用文字键加 danger 色，不加实心红。
- **能按的都有壳，壳的形状说明「按」还是「填」**：动作键统一一档胶囊（`--r-pill`）＋细描边＋控件底，输入控件是方角微圆（`--r-icon` 6px）。两者靠形状分，不靠有无边框分——只留一种壳、让另一种透明，结果是透明的那种彻底认不出能点（2026-11-01 在学习卡上撞过一次）。同一颗「换一题」不许在不同屏上长成三种样子。
- **键必须是看得见的按钮**：壳就是「可按」这个事实的记号；透明文字键会被读成说明句，整片入口跟着失去可点感。整行可点的清单行同样算"看得见"——它的线索是尾部 ›、悬停淡底与行间细线，不靠描边。
- **更安静的那一档只给「顺手换个方向」**：跳过、引导、句子中间那种链接（`linkbtn`，无框灰字）。它是替选项，不承担「这里能按」的交代。
- **键旁边不写信息句**：位置（跟在动作组下面）和轻重（描边对红）已经说了它是什么。
- **不写次要标签，让布局自己说**：位置、分组、单位、对齐已经在说这是什么，再加一个「限时」「题目」这类前缀就是同一句话说两遍。判据只有一条——**把这两个字删掉，这块还认不认得出来**；认得出就删。反过来说，删了以后一屏里两段正文分不清哪段是要求，「作答要求」这种分组标签就得留着——它分的是组，不是重复名字。名字不丢：`aria-label` 与悬停提示里仍然写着，纸面上不重复。一屏里删掉的标签越多，剩下的字就越算数。
- **并排的同款必须同一类东西**：一排胶囊里混进一个「点了去别处」的（换模块、整套卷子），或者一排里既有「按了出题」又有「按了换页」，形状就替它们宣布了同权。分不开就换排法——导航退成页脚一行文字键，位置自己会说是导航。
- **空态只说一次**：一屏里同一句「还没有」说了两遍，第二遍就不再是信息；删掉重复的那几处，把可点的东西提到前面来。
- **读数自己说话，不为它另起提示条**：倒计时走到负数就把它自己标红，不弹「时间到」那种条。提示条要占一整条纸面、还要人动手关掉，而这件事实时就写在眼前那个数字上；红一次比说一句准。提示条只留给「不处理就会坏」的事（写不进本地、换包失败）。

## 四 结构

- **全站一条横向基准**：所有屏共用同一个纸宽与缩放，换屏纸边一格不挪；分不分栏只改纸的内部排法。弹层、浮标、划线小窗在纸外，不跟着缩。
- **纸面缩放是整体等比放大**：字、行宽、控件一起变，所以一行字数不变、按钮与字的比例也不变。觉得按钮观感不对，改它自己的高度档，别单独把它从缩放里摘出来——摘了就跟旁边的字不成比例。
- **两栏只在「带材料 + 够宽」时出现**，窄了先收材料栏（400 是下限），再窄退回上下排。作答页与批改页同一档起点：窗口 950 起就左右分栏——写的时候不必一边写一边往上滚看材料。
- **两栏的顶是同一根横线，右栏自己是一屏**：题面、建议结构、经验行、限时和作答框是一件事，一起待在右栏里，不为了对齐把题面搬到左栏去。右栏给死一屏高，上面那几行按自然高度走，作答框吃剩下的高、自己在框里滚。**整页不滚，材料也不滚**——材料整篇摊开在左栏，全屏只有作答框这一处滚动条。材料长得超过一屏时退回让整页滚，那是它的体量决定的，不是布局坏了。
- **单栏正文列封顶 620px**（约 38 字）并在版心居中，两栏由两列各自管。
- **批改页宽窗对照**：左栏「我的答案 / 自述」、右栏「解析 / 参考答案」，主行动「同模块再来一道」钉在分数带正下方——解析再长它也在首屏。窄窗与无答卷的老记录没有对照结构，退回单栏（不建空栏），自上而下：分数 → 主行动 → 我的答案 → 自述 → 解析 → 参考答案。
- **入口屏是卷首目录**：列仍然居中在版心里，**列内一律左对齐、一行一条**——主按钮、去处清单、模块胶囊共用同一条左缘。三档重量各有各的排法，不许给一样的间距：**等距等于宣布等权**。主行动独占第一行（红、48 高，与清单行同档），其余去处走整行可点的清单行（与画像一级入口同一套：一条顶线 + 行间细线 + 尾部 ›），真实数据行收在清单末尾。
- **卷首两档，按「这一屏在干什么」分，不按哪个函数画的**：入口屏、快判小结、批改页用完整版；作答类工作屏用页眉版。判定只写一处。页眉版不删字——机关名、模块与题型、文号一个不少，公文感立在红线上，不立在大字号上。**两档之间只许缩字号、只许并成一行，不换字族、不换字距、不换对齐基准**：机关名在完整版是宋体加粗字距 4px，页眉版还是这一套，只是 30 缩到 17。换字族会让人以为进了另一个抬头。**红线位置两档也一致**——上距同一个值；换的是上方内容占多高，不是红线在哪。
- **抬头最后一样东西是红线，不是正文**：页眉版把内容并成一行之后，红线到下方正文的下距不能省。省掉就是正文第一行贴着红线，读上去像被红线划掉。
- **作答出口吸底**：作答再长、窗口再矮，出口都在视口里。目前只挂「交卷」这一行。动作条挂在作答框外——框是 `overflow:hidden` 的，sticky 关进去就废成 static。
- **入口屏不摆问句标题，也不摆说明句**：抬头已经报过这是什么，主行动自己就是这一屏要办的事。脚注只在走不通时说话。
- **入口底部只用真实数字压空白**（已练 N 题、平均得分率），不塞说明句。各题型满分不同，平均的是得分率不是分数。
- **训练链步骤条报「进度」不是「一排按钮」**：摆在题目之前，不可点也不给 hover——看着能点却点不动，比没反馈更糙。
- **行内工具归属于内容**：换题跟题干，限时跟作答框。
- **抬头那一行只报一次**：模块与子类型、当前状态、文号，三样各就各位，纸面不另起一行说同样的话。
- **提示条只装运行时才知道的事**：端口退让、换包失败、小更新提示。常驻的招呼话不进这个区——同屏红按钮、脚注、引导气泡已经在说同一件事。

## 五 会踩的坑

眼睛看不出来的，不写下来下次还会犯。

- **不用 `-apple-system` 顶在字族前面**：它把拉丁与数字交给 SF、汉字交给苹方，一行字里两套骨架。不是回退失败，是两种字拼在一起。
- **`--hei` 与控件字族同一族**：屏幕上黑体与雅黑都是同一种无衬线，层级靠字重与字号分，不靠换族。
- **`<small>` 必须显式写 `font-size`**：不写就按浏览器的 `smaller` 算，父级 13px 时算出 10.8px，悄没声地掉出五档。
- **控件 `line-height` 定死 1.35**，不许继承正文的 1.7，否则一个按钮就 40px。
- **字宽要真的放得下**：占位字、极值数字按实测宽度留余量，别用「看着差不多」。
- **`text-indent` 是继承属性，`inline-block` 会二次应用**：父级的负缩进会在子元素首行再走一遍，字被推到纸面之外。写悬挂缩进时要在子元素上归零。
- **纸面里每个直接子元素都带入场动画**，动画末帧的 `transform` 算出来是单位矩阵而不是 `none`，那个盒子会成为 absolute 子元素的定位基准。所以覆盖层挂在纸外。
- **`--canvas` 是桌面底板色**，铺进纸上就是一抹灰。可点行的悬停底用浅纸色。
- **输入框里的技术串用雅黑不用仿宋**：仿宋里 l / 1 / I 长得一样。
- **用 sticky 不用 fixed**：纸是 `overflow:clip`，fixed 会飘到纸外；sticky 的滚动容器是视口，内容短时就在原位。别改成「滚到某处再 fixed」——纸面缩放一变就错。
- **sticky 别关进 overflow 框里**：`overflow:hidden` 的祖先会把 sticky 废成 static（交卷条曾因此在 900×600 掉出视口）。它因此挂在作答框外——别为了「视觉上是一个框」把它塞回去。
- **顶栏对齐的是版心左缘，不是纸边**：新顶栏行照抄同一个边距变量，否则跟提示条各认一根线。
- **重绘就要重新对位**：任何一屏重绘后都要重摆引导光斑，换过按钮再重绘尤其要。

## 六 两端差异

- **两端各是各的正确解，不追求一套通吃**：mac 落苹方（真 Semibold），Win 落 SimHei 的伪粗，后者正是公文标题在 Windows 上的标准样子。别为了看起来一样去抹平。
- **mac 关窗不等于退出**：应用驻留 Dock。**本地服务必须跟着活**，服务停了就是一片白屏。
- **Windows 默认可视高要补回标题栏**：不补则两端内容高差 32px、纸面落不同缩放档，小屏笔记本还会被任务栏裁掉底边。
- **仿宋描边只挂 mac**：华文仿宋比 Windows 的仿宋细，Win 的 SimFang 自带 ClearType，再描一层就糊。
- **可编辑区右键要自己给**：Electron 默认不弹编辑菜单，粘贴不了答卷在 Win 上会被读成「软件坏了」。

## 七 引导

- **光斑只靠暗场说话，不另描红边**：周围已经压暗，再描一道边叠在红按钮上就是描了两道。
- **圆角跟着目标走**：目标是胶囊，光斑就做胶囊；固定 8px 套在胶囊上是外方内圆。
- **留白四边相等**：框住的和框里的尺寸对不上，说明框的是上一版布局。
- **落点跟着主行动走**：指着一颗已经降级的胶囊说「点这里开始」，比不指更糟。

## 八 文案

- **写宽泛、贴用户视角，别写死实现**：说「本地」，不说「这台电脑」「localStorage」这类实现一变就要跟着改的词。
- **说人话，不说产品名**：自造术语和括号解释一律不留。
