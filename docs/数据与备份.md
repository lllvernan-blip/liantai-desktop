# 数据与备份

四个 localStorage 键：`gw_state`（设置、画像、学习卡、笔记、整卷）、`gw_history`（练习记录）、`gw_draft`（草稿）、`gw_marks`（划线）。后三个装的是不可再生的手写内容。

## 只读模式

任一键 JSON 解析失败（坏 JSON 或形状不对）就挂起所有写入，顶部横幅点名坏键并给「导出原始数据」。原始快照不解析、不删键，可能含 API Key，勿外传。导入一份有效备份是用户显式恢复：拿到合格对象后解除只读，导入失败则把只读状态与本地存储原文一并还原。

## 备份文件

导出走 `exportPayload()`：克隆 `state` 后删 `settings.apiKey`，另带 `drafts`、`marks`、`schema`、`appVersion`、`exportedAt`。`schema` 当前为 1；高于 1 的备份拒绝导入并提示升级，本机数据一字不动。没有 `schema` 字段的旧备份按 1 兼容。导入不吃文件里的 provider / baseUrl / model / apiKey。

## 恢复不整份替换

练习记录按「时间戳 + 题面哈希」判同一条：本机列表与备份列表取并集，同键只留本机那条，按时间戳倒序，超过 200 条裁最旧。旧备份 1 条并入本机 3 条得到 4 条，重复那条不进来。草稿与划线沿用「本机已有的不覆盖」。

## 启动滚动备份

每次启动由页面把 `exportPayload()` 交给主进程，写到 `userData/backup/backup-YYYYMMDD-HHMMSS-mmm.json`：先写 `.tmp` 再改名，按文件名轮转只留 10 份。主进程只认固定文件名，路径拼接与越界校验都在主进程，并再兜一层删 `settings.apiKey`。设置页「启动备份」列出各份时间，点「恢复这份」读回原文走 `applyBackup()`，与文件导入同一条合并路径。启动时本地数据读失败就不写这一份，免得空状态占掉 10 份里的名额。

## 记录字段

每条练习记录带 `model`（当时用的模型名）与 `scoringVersion`（判分口径版本，只作标记，不参与计分）。旧记录由 `migrateHistory()` 补空字符串，补过一次即幂等；判分语义与 `recordTotal()` 不变。
