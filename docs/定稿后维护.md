# 定稿后维护

冻结之后不升版本号、不发版。这份只写「哪些还能改、动了会牵连什么」。

## 改评分口径要动哪些文件

- 判分语义在 `app/index.html` 的 `SCORING_RULES`（三档判法、评分校准句）与 `GEN_POINT_RULES`（采分点子项、`need` 的写法）。改一句就等于改了给分标准，先跑 `tools/drift.mjs`，基线必须两份答卷都跑。
- 总分唯一实现是 `recordTotal(h)`，`totalOfGrade(g, moduleKey)` 供跨题比较；画像均分、子类型统计、调度基准分都走它，不许另起从维度分算的聚合。`grade.total` 只存折百分制，维度分只做诊断。
- 题型表以官方大纲为准；改 `MODULES` / `GONGWEN_TYPES` / `PD_FORMS` 必须同步 `docs/题型规范.md`。
- 断言在 `tests/assertions.js`。行为改了就重算预期值并写清为什么，不许删用例、放宽判断或 skip。改完跑 `npm run check`，改界面再跑 `npm run audit:layout`，涉及窗口与启动再真跑 `npm start`。
- 细则见 `docs/AI调用.md`、`docs/训练机制.md`、`docs/验证工具.md`。

## 发版之后还能改什么

- 材料池：`materials/pool/` 的改动进 git，审材料就是看 diff。用 `npm run materials:pack` 发到固定 tag 的 prerelease，不跟安装包走；应用启动自己拉，拉不到一律没声、回落编材料。池子有未提交改动就不许发布。
- 官网：`site/latest.json` 由线上 Release 生成，两个平台的包都齐之后才跑 `npm run site:data` 并推送。`site/index.html` 里写死的那份只是占位兜底，正常路径读线上数据。
- 提 version、push、tag、Release、prerelease、`site:data`、Windows 打包与真机验证都留人工，不在日常维护里顺手做。
- 日志在应用数据目录 `userData/logs/startup.log`；设置页「打开日志目录」直接定位。

## 私钥

- 位置 `~/.liantai-release-key`（0600），不进仓库、不上传。`release:mac` 给每个 zip 签 `.sig`，没私钥就停手不传。
- 丢了：已装版本只认钉进去的那把公钥，会拒绝一切更新，只能手动下一次安装包恢复。换钥要先把新公钥加进 `MAC_UPDATE_KEYS` 发一版，再用新私钥签下一版。换机器发版要把私钥拷过去，或用 `--key` 指到它。
- 材料包签名用同一把私钥，完整流程见 `docs/发布与更新.md`。
