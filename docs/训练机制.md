# 训练机制（细节）

本文件承接 `AGENTS.md` 里训练链、学习卡、作答限时、闭环复测三块的机制：常量值、字段名、函数名、当前实现方式。**判断与禁令在 `AGENTS.md`**。

## 训练链与学习卡

- 只有申论走三步（`FLOW_STEPS`：读材料含找点 / 一稿 / 批改）。
- 链前先摆一整页学习卡（`f.cardSeen`，不进步骤条）；两科都是先看学习卡再动手，卡阶段不亮题面。
- 归类降级成一稿页上的入口（`f.orgOpen`）；沉淀并进批改页（`_lastDistilled` 异步跑完由 `paintExpLine` 就地补一行）。提纲不占归类页，落在一稿页默认收起的 `#outlineBox`。
- 批改结果只从 `state.history` 派生（`gradeForFlow`：先按 `flowId`，老记录的 `legacy-*` 占位退到题目签名）；`lastGrade` 只是当次缓存、带 `flowId`，不跨链复用。取不到就退回一稿，不留空白页。记录页的行可点，`openHistRecord` 走同一条派生路径打开那次批改。
- 综应A 没有训练链，当前题、作答阶段与限时起点另存 `state.resumeZy`（`syncZyResume` 在出题、卡→作答、限时起算/改时长时写）；刷新后首页给「继续」，交卷与完成出口清掉。快照过 24 小时不再提示。
- 出题在途时换页：`reqSeq` 只决定要不要自动上屏；`pendingGen` 记 `origin`，回首页 / 起题科目的起始页按 running / ready 恢复等待页或直接进题，失败在原位报一声；等待页的「取消这次出题」清掉 pending。
- 批改页的「完成」= `closeFlow` + 回首页；首页「继续」入口只给真没做完的链——已批改且仍停在「批改」的不进 `resumableFlow`（收口只影响入口，记录照样留着）。
- 写与读材料时卡以浮标 + 抽屉常驻，浮标挂在 `#docBody` 之外的 `#fabSlot`（纸面内的 transform 会成为 fixed 的包含块）。
- 学习卡 `example` 是「这类题长什么样」的全新示例，prompt 明令不得复用本题材料情节；翻卡计次只属作答阶段。

## 作答限时

- 控件是 `#inpLimit` 一个数字框，`normLimitMin` 是唯一口径：留空 / 0 / 填不出 = 不限时；小数取整；超 `LIMIT_MAX`(600) 按上限。
- **失焦或回车才生效**，生效后回写规整值；单位「分钟」只在填了数字时才露（`.tlin:placeholder-shown + .tlunit{display:none}`）。
- 锚点 `limitMin` / `limitFrom` 挂训练链（`sanitizeFlows` 的 `Object.assign` 保留未知字段），综应A 挂 `current`。
- 时限记 `state.settings.timeLimit`，下一题沿用。
- 控件在题目行与作答区标题行、行右饰收在 `.secright`；换时长**不重渲**（`setTimeLimit` 就地改）；已起算的题只改总时长、沿用同一起算点；时钟只开一个（`_timeTick`）。
- 交卷停表 `setLimitState(limMin, 0)`。
- 到点只 `banner` 报一声 + 剩余时间转「已超时 mm:ss」（`--warn`，剩最后 5 分钟就转），不弹阻断框。
- 用时记 `h.timeLimit` / `h.usedSec`；批改页报「本题限时 N 分钟 · 用时…（超时…）」；不设限时就什么都不写（不臆造 0）。
- 记录表「用时」列（`usedCellHtml` / `fmtClock`）：没计时的留「—」，超时的把超了多少写在后面并转焦橙。

## 闭环复测

- 注入顺序（`activeExperiences`）：还在犯的（recur 多的在前）→ 该核 / 该复测的（没核过，或已改但过了 `RETEST_DAYS = 7` 天）→ 刚核过且已改的**不再占名额**：`expDueRetest` 为假时直接排除，不再“名额不够就塞回去”。
- 回执证据（`applyExperienceChecks`）：`again/fixed` 必须带 `evidence`，且去掉「」后的引文要能在答卷里找到；`again → recur+1、cleared=false`；`fixed` 先过本地核对——同 `kind` 不能再有未满分项（满分项 kind 是 `-`，不能反过来要求存在同 kind 满分项）；同题 `fixed` 只记 `pendingAt`（待换题验证），**换题 + 本地通过**才 `cleared=true` / `verifiedAt`；无 `sourceSig` 的老经验只算待换题；`na` 也要 evidence、记 `naCount`；没 evidence、引文不在答卷、`title` 对不上、本地冲突、未知 status 都进 `rejected`，不改状态。
- 历史 `expCheck` 记 `again/fixed/pending/na/rejected` 并带 `v:2`；旧记录没有 `v`，批改页退回「这次没再犯（旧记录）」，画像把旧 `cleared` 单列「旧记录」，不冒充换题验证。以前只存前两类，分母永远算不出来。
- 批改没有采分点（`hits` 为空）时，`again/fixed` 一律进 `rejected`（`no-hits`）：没有可核的证据，不许改状态。
- 批改页那行与画像三态都用这份结果，别另存一份。
- `storeExperiences` 是 kind 的关卡（只有错因类且属标签表那几类才落进 state）；**这次没给 kind 不许把已有的冲掉**。
- **沉淀不占一步**：提炼结果就近补进批改页，经验库管理在画像的经验页。

## 快判（第四屏）

- 一轮进行中 `pdActive` 置真、`_view = "pd"`——判别轨是独立的第四屏：不挂 `_view` 会被首页那支报成「首页」，与文号的「快判」自相矛盾。
- 请求体由 `genPDRound` 组装，`weakTraps` 由 `pdWeakTraps` 供（见 `docs/AI调用.md`）。
- `PD_FORMS` / `PD_FORM_ORDER` 只当出题引擎用；界面上的入口只有首页红按钮。
- 出题失败回到出题前的现场：上一轮已收尾就回小结（回到那道题的「看本轮小结」上，它的翻页守卫会把人钉在原地）。

## 材料来源：有据 / 编材料

- 两条路，**主路 + 兜底**：`poolPick(poolTopicsFor(k))` 从材料池取到骨架就走有据（`groundedSpec`），取不到（池子空 / 页面不在桌面壳里 / 读失败）就回落到编材料（原 `matSpec`）。**取不到不报错，不算异常**——材料出不来是常态。
- 选材主题只走一处：`poolTopicsFor(k)` 从 `PD_TOPICS` 白名单按权重抽一个；`poolPick(topics)` 里的 `preferTopic` 负责优先匹配主题，对不上仍兜底给一篇。**别在调用点另写一套主题表**。
- 骨架由 `tools/material-pool.mjs` 抓取提炼，落在 `userData/材料池/`；取过一篇就记进 `userData/pool-used.json`。位置跟着 userData 走，**测试副本的池子与正式版自然分家**。可抓取源也是白名单：政府网政策文件库 / 人民网多频道 / 人民日报电子版（`SOURCES`）。
- 界面是沙箱（见 `AGENTS.md`）：池子只经 `preload.js` 那三个只读口子（`poolPick` / `poolList` / `poolStat`）进出，读写与路径校验全在主进程 `poolHandlers()`。
- 用过的那篇标题记在 `question.fromPool` 上，素材的媒体 / 日期 / 主题另存 `question.src`；两样都跟着题目进练习记录、一起导入导出，不会丢。`fromPool` 也是题面上那个小标的开关（`fromMatTag()`）。
- 编材料与有据**共用其余一切**：采分点规则、字数表、学习卡、档位、批改链都没变，差异只在材料那一段怎么写。

## 申论整卷

- 入口在申论科目起始页；一次取 3–4 篇材料池骨架，拼成 5,500–6,500 字的共用材料，再逐题出 5 题（15/10/20/20/35），**不是真题原文**。题序与作答上限按真卷：归纳 350 / 分析 300 / 贯彻执行 400 / 对策 400 / 申发 1000–1200。
- 材料分四段专题（`给定资料1` 银发 / `2` 固态电池 / `3` 非法码头 / `4` 汽车安全）；每题只准打一段，禁止把四个领域并列进一道题。综合分析必须引用该段材料原句；申发论述用能统摄四段的总命题，不摘案情/企业名，避免只扣一段。
- 题干一律带 `给定资料N` 锚点与分值；归纳、讲话稿、作文用固定题面收口；同卷不重复文种（讲话稿不写成展板/意见建议）。归纳/讲话稿/作文不再让模型自由加身份、参会名单、门牌号。
- 采分点按整卷口径：4–6 条，每条 need 2–3 条；不再按单题 6 条 need 拆成二十多个原子事实。
- 材料不足 5,500 字自动重拼一次；5 题共享材料；作答不走三步链，直接进作答/批改页；批改结果写回 `state.paper` 与练习记录，一次只留一套，跨重启恢复。
- `state.paper` 只存一份材料；每题的 `question.background` 在打开该题时才填入，避免同一份 6k 材料存五遍。`sanitizePaper` 负责导入/启动时的逐项校验。
