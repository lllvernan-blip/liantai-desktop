# 找点与归类一起下线

日期：2026-11-01 · 状态：已实施

## 背景

申论那条链上，读材料步除了划线还有一层「找点」：句子表（`sentenceTable`）、句级吸附（`snapSentence`）、选区记录（`addFreeSelectionRecord` / `toggleSentenceSelection` / `pickListHtml`），挑出来的点收进 `flow.selections`。一稿页右侧有个「先归类再写」的入口，点开是归类面板（两组：先逐点归组、再给每组起上位词），产物是 `flow.groups`，最终 `buildOrganizeOutline` 拍成一行一个类的纯文本，作为 `organizeOutline` 随卷塞进批改请求体，prompt 里还专门写了一句「提纲只供诊断，不参与计分」。

这条链唯一的出口就是那份提纲。提纲没了，找点就只剩一个不收任何东西的控件。

## 决定

1. **归类整块下线**：删掉面板、两段式流程、组名输入、已归进度、归属反查表与提纲生成，一稿页那一行不再有「先归类再写」。
2. **找点随之一起下线**：句子表、句级吸附、选区记录、已找点清单全部删掉；材料上只剩划线一层。理由是它唯一的消费者是归类提纲。
3. **划线保留**，仍走 `gw_marks` 那一份，与综应共用同一套；材料标记只剩「底色 + 2px 底边线」这一层。
4. **批改 prompt 去掉 `organizeOutline`** 与那句「只供诊断」的口径。
5. **老的「停在归类那一步」的链**继续落到「一稿」，不整条消失——`sanitizeFlows` 里那条规定原样保留。

## 判据

- **考场上没有那一步**。归类面板是一个练习台自造的动作，练它带不走；划线和学习卡抽屉里的笔记已经覆盖了「读的时候留下线索」这件事。
- 一个控件不收任何东西，比没有这个控件更糟：摆在那里等于在提示「这里该有产出」。
- 同一件事不存两份：一稿页已经有划线回顾与笔记，再摆一层归类提纲，是把「理要点」这一件事写了两遍。

## 落地

- `app/index.html`：删掉 `sentenceTable` / `snapSentence` / `toggleSentenceSelection` / `addFreeSelectionRecord` / `pickListHtml` / `dropSelections` / `holderOf` / `groupLabel` / `buildOrganizeOutline` / `organizePanelHtml` / `orgHeadHtml` / `orgGroupPanelHtml` / `orgNamePanelHtml` / `orgPhaseOf` / `wireOrganize`；`mergedMaterialRange` 退化成只按划线切段；`submitAnswer` 的 attempt 不再带 `outline`；`sanitizeFlows` 与 `ensureFlow` 去掉 `selections` / `groups` 两个死字段；清掉 `.pt-seg` / `.pickline` / `.og*` 共 46 行只服务这套功能的 CSS，以及 `--pick-bg` / `--pick-line` 两个只剩它在用的色值。
- `tests/assertions.js`：删掉归类两段式、找点选区、提纲进请求体、「归类屏不摆题面」等整块用例（净少 185 行，页面自检 1216 → 1148 条）；「读过材料就能点句子找点」类断言改成「材料上只剩划线」。
- `docs/题型规范.md` / `docs/界面规范.md` / `AGENTS.md` / `README.md`：训练链口径统一改成「读材料 → 一稿 → 批改」，去掉「含找点」与归类入口的说法。

## 实测

- `npm run check` 10 项全过，14.7s：壳侧 233/233 · 页面 1148/1148 · 官网 20/20，布局 22 屏 0 硬问题、软项 2 处与基线一致。
- `npm run audit:layout` 全量 187 屏 × 2 宽度 0 硬问题——归类屏那一档本来就不在扫描清单里，删掉它不影响覆盖面。
- 删的过程中抓到一个真 bug：`submitAnswer` 里 `f.attempts.push({ …, outline })` 的 `outline` 变量随归类一起没了，引用还在。ReferenceError 被外层 `catch` 吞掉，表现为「批改记录写进去了、但链子停在作答步、还弹一条错误横幅」——自检里三条断言一起红。

## 不做什么

- 不给材料恢复「点句子」这类交互。要加也要先有第二个用途，否则又是一层不收东西的控件。
- 不改划线的存法：字符级、按题目签名存、超量淘汰最旧，这套不动。
