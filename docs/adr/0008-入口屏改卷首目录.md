# 入口屏改卷首目录：列内左对齐、一行一条

日期：2026-11-01 · 状态：已实施

## 背景

起始页（首页与两科起始页）自 2026-10-12 起是"整屏居中 hero"，之后四轮（ADR 0001–0005）反复调的是同一簇居中之物的尺寸与顺序。这一轮改完文案（撤副标、撤信息句）之后，用户仍反馈"入口那几屏 UX 和 UI 都怪"，说不出哪不对。

量出来三条：

1. **等距宣布等权**。红按钮、科目入口、恢复键、进度行四组之间一律 24px——间距只有一档，等于说这四件事一样重要，而它们是主行动、去处、数据三档。
2. **一行一条 vs 一行多颗混着摆**。首页同时摆着"快判""综应A 练一题""写一篇申论"三颗胶囊并排——它们是三个**不同性质的去处**，摆成一行胶囊读起来像同一维度的多个选项（模块 chips 那种）。
3. **"整块在版心中线上居中"这条决定的理由是"入口是一页一件事"**，而纸面上实际有 4–5 件。前提已经不成立。

## 决定

1. **入口屏改「卷首目录」**：620 那条列仍然居中在版心里，**列内一律左对齐、一行一条**。主按钮、去处清单、模块胶囊共用同一条左缘。
2. **去处走整行可点的清单行**，复用画像一级入口已有的 `.navrow`（一条顶线 + 行间细线 + 尾部 › + 悬停淡底），**不另造一种按钮**。行 48 高、字 `--fs-title`(17)——两档都在既有阶梯上。
3. **三档重量三档排法**：主行动独占第一行（红、64 高那一档）→ 去处清单 → 真实数据行收在清单末尾。间距走 24（跨组）/ 12（两组清单之间）两档。
4. **模块 chips 保持胶囊**，只跟着左对齐。判据：**同一维度的并列选项**（五个模块名、二十一个文种）用胶囊，**不同性质的去处**用清单行。
5. **说明句那一列不加**。目录式排法本来可以在名称右侧配一句解释（"两科混着出，判完就走"之类），但入口屏的说明句预算冻在 **0**（`tools/entry-audit.mjs`，2026-11-01 起），那个闸门的设计目的正是拦住"顺手补一句说明"。要加就得改规格，另议。

## 不做什么

- **不改竖向居中**。上一轮我曾把"红头到主按钮之间 99px"列为毛病，这条撤回：ADR 0002 定过"动作组在红头下方剩余纸面里竖向居中并整体上提，底部垫高 100px，空白上小下大——下半张纸是公文纸的自然留白"。改完这个数自然降到 51px，是因为清单比原来那一行胶囊高，不是居中被动过。
- **不推翻 620 列居中**。列的位置是横向基准的一部分，只有列**内部**的对齐方式变了。
- **不把模块 chips、文种 chips 并进清单**。五模块六行清单会把进度行与恢复行推出首屏。
- **不做两栏分维度**（左列"怎么练"、右列"去哪练"）：620 列拆两列每列只剩 298px，装不下 48 高胶囊的字，为治排法问题去动横向基准不值；且规范明写"不做左右横版"。
- **不做"一屏只留一件事"**：首页红键要么跟状态走、要么是快判，而快判不挑科目；两科大题的唯一入口就是那两行，删了等于藏掉两个真去处。

## 落地

- `app/index.html`：`.startbox .actions` 与 `.startbox .chiprow` 的 `justify-content` 改 `flex-start`；`.start-entry .subtypechips` 去掉 `margin:0 auto` 居中；新增 `.entrylist`（顶线 + 24/12 两档）；`.actline` 一族与 `.chiprow` 一族随结构下线，不留死样式。
- `tools/entry-audit.mjs`：区域映射加 `entrylist → 主行动`。清单行是按钮，与 `.actions` 同一类，不背说明句的账——**说明句预算仍是 0，没动**。
- `tests/assertions.js`：五条跟着结构改（动作列、恢复行、入口可点性、24/12 间距、快判降级）。

## 实测

- 主按钮、三行清单、模块胶囊、恢复行的左缘**同为 70px**（900×600 下），一条线。
- 字号只用既有档：主行动 28 / 清单行 17 / 模块胶囊 15 / 进度行 15；控件高只用 64 与 48 两档；清单行圆角落在直角档 `--r-flat`（规范里那一档就是给清单行的）。
- 入口文案闸门：合计 **0 字**，strict 判据 PASS——预算没改、没被绕过。
- `npm run check` 9 项全过（页面 1216/1216）。
