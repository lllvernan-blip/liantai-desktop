# 批改页宽窗两栏与主行动位置

日期：2026-11-10 · 状态：已实施

## 背景

11/02 那一轮把批改页定成恒单栏：`body.wide-review #docBody>*{max-width:var(--text-col)}`（620），理由是范文与正文同踩一条左缘，读下来是一条线。

那个理由本身没错，代价是两件事：解析一长，主行动（下一题 / 交卷）被推到屏幕外，得滚过整篇解析才够得着；「我的答案」和「解析」上下排开，改到自己那句时得记住上面那句再往下滚。

## 决定

1. **宽窗改真两栏**：`body.wide-review .grade-columns{display:grid;grid-template-columns:1fr 1fr}`。左栏「我的答案 + 思路自述」，右栏「解析 + 参考答案」。
2. **主行动钉在分数带正下方、解析之前**——解析滚多长，它都在首屏。
3. **门槛与作答页同一条**：`MIN_SHEET_REVIEW = 950`，两栏各 (950-140-32)/2 = 389。窗口 960 起就是左右对照。
4. **窄窗与无答卷的老记录单栏**：`wide-review` 不亮时 `.grade-columns` 不分组，按 DOM 顺序落回一条竖线。

## 判据

- **主行动得在首屏**。批改页真正要做的事是「看完了去下一题」，不是「读完解析」。把它压在解析后面，等于逼人先读完才准走。
- **我的答案和解析要能对着看**。改的是自己写的那句，得同时看到原话和它哪儿不对。上下排开就得在脑子里存一句再滚。
- 389 是下限不是目标：再窄，一句答案断三次行，两栏比单栏更难读。所以窄窗不做两栏。

## 落地

- `app/index.html`：`gradeHtml` 分出 `.grade-columns` / `.gcol` 两层壳；`selfNoteHtml` 挪进左栏；`.nextrow` 提到 `ghead` 之后、解析之前；`MIN_SHEET_REVIEW` 960 → 950；删掉压正文列的那条 `--text-col` 规则。
- `docs/界面规范.md` / `AGENTS.md`：分栏门槛与主行动位置的口径同步。
- `tests/assertions.js`：恒单栏那条改成两栏（判 `grade-columns` 真渲染 + 宽窗有 grid 规则 + 不再压 `--text-col`）；范文次序从「在解析之后」改成「在分数带之后、解析之前」。

## 实测

`npm run check` 10 项全过：壳侧 250/250 · 页面 1164/1164 · 官网 20/20，布局 22 屏 0 硬问题、软项 2 处与基线一致。

## 不做什么

- 不给窄窗做两栏。389 已经是最窄的能读宽度。
- 不改四部分的内部次序：我的答案 → 解析 → 参考答案 仍是主次，自述跟着「我的答案」走——它问的就是「你这题错在哪」，跟原话摆在一起才有东西可对着说。
