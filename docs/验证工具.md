# 验证工具（工程闭环 · 探针 · 漂移）

`AGENTS.md` 的「修改后验证」节只留入口与判据；**细节都在这一份**。做这几件事之前先读它，别凭记忆改工具参数。

## 自检

`node tests/run.mjs`（项目根目录）必须看到 `N/N passed` 且退出码 0。零依赖：它把 `app/index.html` 的唯一 `<script>` 抠出来、配最小 DOM 桩子、在 Node 里跑 `tests/assertions.js`。

两个平台的通过数不一样（不是出错）：壳侧 `tests/shell.mjs` 的第 6 组只用 macOS 的解压与 plist 工具（`ditto` / `PlistBuddy`），别的平台会打印一行「跳过第 6 组」；页面那份两边一样。**别把数字抄进文档**——每加一条断言它就会变。

改动涉及窗口 / 启动 / 加载方式：真跑一次 `npm start`，确认 `logs/startup.log` 里有 `did-finish-load`、没有 `did-fail-load`。涉及浏览器交互、异步请求、设置弹层、导入导出或本地存储：用真实路径走一遍并检查控制台错误。

## 工程闭环（提交前一次跑完）

```bash
npm run check                # 静态检查 + 全量自检（约 5 秒）
npm run check -- --no-tests  # 只做静态检查
npm run check -- --staged    # 密钥只看暂存区（pre-commit 用的就是这条）
```

`tools/loop.mjs` 跑的是**机械可判**的那几类静态检查，再跑一次全量自检；任何一项不过都退出 1（项数会长，别按数字记它，看输出）：

- **语法**：根目录 `*.js`、`tests/` 下的 `.mjs` / `.cjs` / `.js` 与 `tools/` 下的 `.mjs` 逐个 `node --check`（只解析、不执行，碰不到 Electron 与用户数据）。
- **单文件页面**：`app/index.html` 仍然只有一段内联 `<script>`，没有外链 JS / CSS 与 `@import`。这是离线、CSP 与自检的共同前提，破掉时开发态往往还能开。
- **规则文件尺寸**：`AGENTS.md` ≤ 32 KiB（超了会被指令链按字节截断）。
- **版本**：`package-lock.json` 与 `package.json` 同版（与发布闸门共用 `gate.mjs` 里的那一份）。
- **文档引用**：`AGENTS.md` / `README.md` / `docs/*.md` 里指向仓内脚本、文档的路径都真实存在（与发布对账共用 `tools/doc-refs.mjs`）。
- **明文密钥**：按 `gate.mjs` 的 `KEY_RULES` 扫（服务商 Key / GitHub 令牌 / PEM 私钥），命中串打码输出；演示用假 Key 在那一行写 `gate-allow` 放行。`--staged` 时读 `git show :路径`，所以「工作区删了、暂存区里还留着」也能拦住。
- **闭环入口**：`package.json` 的 `test` / `check` / `check:staged` / `hooks:install`、`.githooks/pre-commit` 与 `.qoder/settings.json` 的 Stop 钩子都还接在 `loop.mjs` 上（改文件名时最容易只改一边）。
- **入口屏文案**：把 `tools/entry-audit.mjs --strict` 当闸门跑（判据：流程句、机制词、跨屏重复口径、合计字数）。预算数是砍完之后冻结的实测值、**零余量**——加字就红，砍字就把这个数往下改，不许往上留空间。要看现状单独跑 `npm run audit:entry`。

最后跑一次 `node tests/run.mjs`，解析三份自检的 `N/N passed`；`--no-tests` 跳过这一步。

红了先看它列出的项目与判据，再按这张表处理：

| 项目 | 常见原因 | 怎么修 |
| --- | --- | --- |
| 语法 | 新脚本有语法错误 | 按报错的文件与行号改，`node --check 文件` 单独复跑 |
| 页面 | 多了第二段 `<script>`、外链 JS / CSS 或 `@import` | 并回唯一那段内联脚本；资源改内联——离线、CSP 与自检都靠这一条 |
| 规则尺寸 | `AGENTS.md` 超过 32 KiB | 把细节挪进 `docs/`，正文只留判据与入口 |
| 版本 | `package.json` 与 `package-lock.json` 不同版 | 改完 `version` 跑一次 `npm install --package-lock-only` |
| 文档引用 | 文档指向的文件改名或删了 | 改路径，或把文件补回来 |
| 密钥 | 扫到服务商 Key / 令牌 / 私钥 | 删掉并轮换；演示用假 Key 在那一行加 `gate-allow` |
| 闭环入口 | npm scripts 或钩子没接在 `loop.mjs` 上 | 按提示把缺的那一处接回去 |
| 入口屏文案 | 入口屏加了说明句 / 流程句 / 机制词，或合计越过预算 | 先把这句删掉或并进已有口径；真该留的就按 `npm run audit:entry` 的实测值把预算改成新读数（一次只改这一处，别顺手放宽） |
| 全量自检 | 某条断言不过 | `node tests/run.mjs` 单独跑，按 `FAIL` 行定位 |

**装钩子**：`npm run hooks:install` 只把本仓库的 `core.hooksPath` 指到 `.githooks`（换台机器要重装；撤掉 `npm run hooks:install -- --remove`）。它**不会**自动装。

**在 Qoder 里自动跑**：项目级 `.qoder/settings.json` 配了一个 `Stop` 钩子（只在打开这个项目时生效），任务结束时经 `.qoder/hooks/stop-check.sh` 调 `tools/qoder-stop.mjs`：

- 工作区干净，或这份内容刚查过（stamp 落在 git 目录里的 `liantai-loop-stamp.json`，不进仓库）——直接放行，问答类任务没有等待。
- 没过时退出码 2，把失败输出回给模型去修；**同一份内容只拦一次**，防止反复停下。改了任何内容就会重新查。
- 钩子超时 120 秒，全套检查通常约 5 秒。不想让它跑：删掉 `.qoder/settings.json` 里的 `hooks` 段（或整个文件），不影响 `npm run check` 与 pre-commit。
- 它和 pre-commit 用的是同一个 `loop.mjs`，区别在时点（任务结束 / `git commit`）与密钥扫描范围（工作区 / 暂存区）。

两个边界要知道：

- **两个钩子看的范围不一样**：pre-commit 读「暂存区的密钥 + 当前工作区的其余检查」，**部分暂存**时没暂存的那部分也会参与自检——红了先 `git stash` 或把整份改动一起暂存；Qoder Stop 钩子只读工作区，不读暂存区，工作区干净就直接放行。
- **两者都不是发布闸门**：工作区干净、远端 `main` = 本地 `HEAD` 这两条在提交 / 任务结束时天然不成立，留给 `npm run release` 开头的 `tools/gate.mjs`。

## 探针（量一段真行为）

```bash
node tools/probe.mjs 我的探针.js
```

它把 `app/index.html` 的脚本抠出来、配最小 DOM 桩子跑，探针里可以直接用应用的全部函数与常量（`MODULES` / `moduleAvg` / `gen` / `pickSubtypeFor` …），也支持顶层 await。探针是一次性的，用完删掉，别往 `tests/` 里塞。

**别用 `node -e` 写带 JSON 片段的探针**：参数里只要同时出现「冒号」与「反斜杠」，Git Bash 就会把这段当路径列表改写（`\"` 变成 `/"`、`\\` 变成 `//`）。轻则语法错误，重则搜索串被悄悄改掉、程序照跑并返回 `false`，看起来像「功能没生效」，能白排查半天。`MSYS_NO_PATHCONV=1` 与 `MSYS2_ARG_CONV_EXCL='*'` 都治不住，老老实实写成文件。

## 阅卷漂移（同一份卷子反复批会不会给不同分）
```bash
node tools/drift.mjs prepare    # 真接口出一道题，落成 <系统临时目录>/liantai-drift-case.json
# 打开那个 JSON，把 answers.clear（写明具体事实）与 answers.edge（八条全点名、零细节）都写好
node tools/drift.mjs run 5      # 每份答卷批 5 次，打印各次得分、极差、哪几个子项在摆
```

它走的是 app 里真实的 `gen()` / `grade()`，不是另写一份 prompt。**基线必须两份答卷都跑**：2026-09-29 第一次只测了「写具体」那种，5 次一字不差、极差 0，看着像根本没病；换成「只点名不给事实」的答卷才暴露出来（极差 4.5/20）。

**Key 不用手动设**：不给 `LIANTAI_KEY` 时，它从本机应用数据目录里取已存的 Key（测试副本优先，再正式版），逐个试到能连上为止；都不行才报错。取来的 Key 只用在内存里，不写仓库、不打印。环境变量仍然优先，想指定别的账号就设它。`LIANTAI_MODEL` 可换模型（默认 `deepseek-flash`）。

Key 的读取路径写死在 macOS 的 `~/Library/Application Support/<app>/Local Storage/leveldb`；Windows 下暂时要自己设 `LIANTAI_KEY`（本机已没有 Windows 环境验证）。

## 材料池（抓一手材料 → 提炼骨架 → 落盘）

```bash
node tools/material-pool.mjs fetch gov 养老服务 3   # 政策文件库（按关键词搜）
node tools/material-pool.mjs fetch rmw 10            # 人民网社会法治（按栏目拿最新）
node tools/material-pool.mjs list                    # 看池子里有什么（不连网）
node tools/material-pool.mjs verify 15               # 抽 15 条回原文核（规范第七节的验收线）
```

规矩全在 `docs/材料规范.md`（第四节选材、第五节提炼、第八节时效），**这里只实现不另立口径**。与 drift 同一套路子：把 `app/index.html` 的脚本抠出来配 DOM 桩跑，所以提炼走的是应用里真实的 `callLLM`（降级阶梯、空输出重发、撞额度翻倍都在），不是另写一份请求。

**只落骨架，不落原文**（规范第五节）：原文只在抓取过程中用一次，跑完就丢。代价是提炼错了回不去，所以每批必须 `verify`。

**`verify` 判三种，只有 `supported` 算过**：`partial`（原文写了但条目把话说满了、或改了数字与限定语，如「近三成」写成「30%」）与 `absent`（原文根本没有）都计入错误。**它只报不改**——错的是人，不是脚本悄悄擦掉就算完。

池子目录默认 `~/练习台材料/池子`，用 `LIANTAI_MAT_DIR` 换。**提炼一次真调用一篇**，抓网页不花钱；`verify` 按篇调用（一篇一次，不是一条一次）。存不进池子的（入库判断不过）不落盘，也不花第二次钱。

两个容易踩的地方：

- **政策文件库的子库名写错不报错**，静默返回空。所以 `search()` 拿到结果必须断言条数，并核对标题里真的含检索词（不带 `searchfield=title` 会返回全量，看着有数据其实没筛）。
- **正文地址是 `.htm` 不是 `.html`**。拼错会拿到一张「您访问的页面不存在」的页面——它同样是 HTTP 200，只有看字数才知道上当了。

**新闻源的三个坑（2026-10-15 实测，详见规范第三节）**：

- **不能一律按 UTF-8 解**。人民网社会法治频道是 UTF-8，但它家时政频道是 `gb2312`；`r.text()` 只认响应头里的 charset，头里没写就按 UTF-8 解——**GBK 页会静默变成满页乱码，HTTP 还是 200**。所以工具自己读字节自己解码（先看 HTML 头部声明，再退响应头）。
- **不能「取前 N 篇」**。列表页里混着图片新闻（正文不到两百字），实测一屏 11 条里 5 条是图片新闻。得往后取，正文够长（`MIN_BODY`）的才凑数。
- **新华网地方频道整页停在 2022 年**（标题、链接、日期都对，内容全是三年前的，HTTP 200）。这种「静默过期」比报错危险——不报错就发现不了。新华系不用。
